# us-sanctions-research · 美国经济制裁合规研究工具

本工具将美国经济制裁的法律检索整理为一套可供公司法务与合规人员使用的工作方法，覆盖从名单筛查、法源核查、行为定性、许可证判断到留痕与持续监控的完整环节。工具仅负责汇集客观事实、形成工作底稿、监控名单变动；**法律判断须由合规官或律师作出**，工具不替代专业意见。

> **免责声明（简版）**：本工具仅供研究参考，不构成法律意见。OFAC 名单与通用许可证（GL）持续更新，检索结果建议有效期不超过 7 天。最终合规决策须咨询具美国制裁执业资格的律师，并以 OFAC 官方实时数据为准。美国经济制裁与出口管制（BIS）可能同时适用，须分别评估。

---

## 一、定位与适用场景

**适用对象**：公司法务、合规岗及其他需要就美国经济制裁做尽职调查或风险评估的人员。

**适用情形**
- 对某一主体（自然人、企业、船舶等）做美国经济制裁维度的合规检索；
- 评估一笔涉美交易（涉伊朗、俄罗斯、朝鲜、古巴、委内瑞拉等）是否触碰 OFAC 制裁；
- 定位某一国别或专项制裁计划、通用许可证（GL）及近期执法动向；
- 建立制裁名单的持续监控机制（名单或 GL 变动告警）。

**工具定位**
- 名单筛查环节借助已安装的 `sanctions-screening` skill（覆盖 OFAC 及 100 余个全球制裁名单，可附证据截图），本工具不再重复实现；
- 本工具负责将检索过程组织为固定工作方法，并生成可归档的研究备忘录与监控报告。

---

## 二、使用要求

为保障合规安全，使用时须遵守以下要求：

1. **不下合规结论。** 工具只输出"查到 X""未发现 Y""建议就 Z 项作进一步评估"，不得得出"可以交易""已放行""合规通过"等结论。
2. **以官方实时数据为准并标注时间。** 名单、GL、执法信息优先取自 OFAC 官方来源；任何结论均注明检索时间（UTC）。
3. **附免责声明。** 每次交付均须附带文末免责声明。
4. **存疑即上报。** OFAC 采严格责任原则（无论是否善意、是否知情均可能受罚），遇有不确定应标注"需人工复核"，不得直接放行。
5. **区分 OFAC 制裁与 BIS 出口管制。** 二者主管机关、清单与法律依据不同，一笔交易常同时触发。本工具仅覆盖 OFAC 线；涉出口管制须另行核查 BIS / Entity List。

## 三、工作方法（七个环节）

| 环节 | 内容 | 执行方式 | 产出 |
|------|------|----------|------|
| 1 | 法源依据与制裁计划覆盖核查 | 部分借助工具 | 适用制裁计划清单（防漏查核心） |
| 2 | 名单筛查 | 工具（sanctions-screening） | 命中 / 清除 / 存疑，附证据 |
| 3 | 国别 / 专项计划定位 | 工具（抓取官方页面） | 计划限制摘要，与环节 1 交叉核对 |
| 4 | 行为定性（50% 规则 / 二级制裁 / 连接点） | 人工 | 待决法律判断清单（不下结论） |
| 5 | 许可证路径 | 部分借助工具 | GL 适用性比对表（决策在人工） |
| 6 | 留痕与报告 | 部分借助工具 | 研究备忘录（判断部分留空待签核） |
| 7 | 持续监控 | 工具 | 名单变动 / 关注实体状态 / 定期告警 |

**环节 1 说明（防漏查重点）**：根据主体所涉地理、行业、行为线索，列明所有可能适用的 OFAC 制裁计划（综合制裁、专项计划、反恐 / 网络 / 毒品等横向计划），并梳理其"授权制定法 → 行政令（EO）→ 31 CFR 章节 → 主要被制裁群体"的法源链，形成覆盖清单，供合规官逐项核对是否遗漏某一计划或某一关系（例如客户与某一武装组织的关系）。配套审计卡见 `references/coverage_audit_card.html`。

## 六、监控脚本 `monitor_ofac.py`（可独立运行）

仅依赖 Python 标准库，无需第三方包。

```bash
# 默认监控 OFAC SDN 列表，首次运行自动建立基线
python scripts/monitor_ofac.py

# 监控综合清单（Consolidated）
python scripts/monitor_ofac.py --list consolidated

# 启用关注实体级告警（默认自动加载同目录 watchlist.json）
python scripts/monitor_ofac.py --watch scripts/watchlist.json

# 指定基线文件与输出报告
python scripts/monitor_ofac.py --baseline base.json --out report.md

# 覆盖默认下载端点（OFAC 调整地址时用）
python scripts/monitor_ofac.py --url https://ofac.treasury.gov/downloads/sdn.xml
```

**运行行为**
- 首次运行：写入基线（SHA256 + 条目名），报告"基线已建立"。
- 后续运行：比对基线，报告新增 / 移除条目及 hash 是否变动。
- 加载 watchlist 后：额外报告每个关注实体的当前状态与变化（新被列入 / 已解除制裁 / 在名单中）。

**`watchlist.json` 说明**
- 仓库内 `watchlist.json` 为**示例占位**，不含任何真实关注实体。
- 请在本地自建真实清单：复制该文件，删除示例条目，填入要监控的实体关键词（大小写不敏感子串匹配）与备注。
- 改完后的本地文件**不要**执行 `git add`（占位版已入库；保留本地真实版即可让每日监控聚焦你的实体）。
- 若 `watchlist.json` 不存在，脚本回退到内置默认关注实体（Zanjani / Dot One / 胡塞 / BITBANK）。

**每日自动监控（可选）**：用 `automation_update` 建 recurring 自动化（如每日 09:00），调用 `monitor_ofac.py --watch scripts/watchlist.json`，发现关注实体新列入 / 解除即经邮件等渠道告警。

## 七、法源与漏查防护参考

- `references/legal_authority_lookup.md`：法源检索链（授权法 → EO → CFR → 计划 → 被制裁群体）、主要计划法源索引、也门实例、**伊朗 / 也门 / 俄罗斯 / 朝鲜 / 叙利亚 / 古巴 / 委内瑞拉深度细化**。
  - 关键编号（起始索引，正式出具意见前请以 OFAC Legal Library / eCFR 实时复核）：伊朗 ITSR = 31 CFR 560（EO 13902 落于其下）；也门 = 31 CFR 543，胡塞 SDGT = 31 CFR 594（EO 13224）；俄罗斯 = 31 CFR 587（EO 14024）+ 589（乌克兰 / 俄相关）；朝鲜 = 31 CFR 510；叙利亚 = 31 CFR 542；古巴 = 31 CFR 515；委内瑞拉 = 31 CFR 591。
- `references/coverage_audit_card.html`：可勾选审计卡，逐项确认是否漏查某制裁计划 / 关系，可打印 PDF 存档。

## 八、局限与注意事项

- **网络依赖**：监控脚本需可访问 `ofac.treasury.gov` 下载列表；离线 / 受限环境无法运行。
- **端点可能调整**：OFAC 下载地址若变更，用 `--url` 覆盖，并同步更新 `references/ofac_resources.md`。
- **非实时保证**：本工具不做法律结论，仅汇集客观事实；正式决策前须以 OFAC 官方实时数据复核。
- **仅覆盖 OFAC**：出口管制（BIS / EAR）、欧盟 / 英国 / 联合国制裁须另行评估。
